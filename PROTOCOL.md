# Study 42: Check the evidence before reporting a research-data link as broken

## Decision and acceptance

When does a failed automated request justify a DOI-link review, and when should a maintainer receive an explicit unknown state? Build a bounded evidence-triage benchmark and offline implementation exercise. Compare an authored naive rule with an authored conservative rule; do not claim a new link-rot detector, production false-positive rate or automatic repair. The historical proposal called for Crossref/OpenAlex, calibrated rules and human-checked references. This exact study uses Crossref relations and DataCite public metadata, fixed rules without statistical tuning, and separately captured agent-inspected browser evidence. OpenAlex and independent human validation are not executed claims. Do not infer that a supporting dataset proves a paper's scientific claim or that a landing response proves data files can be downloaded.

Acceptance requires exact eligible public metadata and rights, preserved requests/originals/hashes, complete fixed identity/exclusion ledgers, separate source dataset DOI groups, both reference classes with unknowns retained, two observations separated by at least twenty minutes, independently recomputed rule/metric evidence, a committed dependency manifest before final-link observations, meaningful fixtures, source-preserving offline replay, three reviewed figures and an independently checked/rendered manuscript. Required source/privacy/scientific/selection/replay/release gates cannot be averaged away. A local 4/5 means these finite acceptance checks pass, not operational reliability or universal truth. Review at most three substantive rounds, 45 active review minutes and 60 review-specific tool calls; retain failed attempts and unavailable accounting honestly.

## Metadata exposure and source rights

Crossref describes member-deposited bibliographic metadata, with broad reuse permission except potentially copyrighted abstracts. DataCite public metadata are CC0. Its public API returns only Findable DOI records; a public API 404 does not prove a DOI was never registered or that data vanished. Use no authenticated/member endpoints, accounts, credentials, paid services, copyrighted abstracts or full articles. Original metadata/HTML and request receipts remain private. Publish only minimal DOI/relationship/type facts, sanitized observation/reference evidence and new calculations. Web/API availability does not grant a right to redistribute underlying dataset files; none are downloaded. Independent program manuscripts may be public after checks; formal-publication projects including Azure optimization remain private.

Prior exposure is documentation and metadata-only count requests, without cohort items or link outcomes. The 2019 Crossref count request returned 3,631 matching works; an immediately following 2023 count request returned 429 with an empty body. Both attempts are preserved. Do not equate that rate limit with a missing source. No 2023 cohort is used. This design uses one fixed 2019 metadata snapshot, separate DOI groups and current observation times rather than claiming a publication-year forecast or first-release liveness backtest. Historical publication dates do not date current metadata availability.

Primary documentation: https://www.crossref.org/documentation/retrieve-metadata/rest-api/ ; https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/ ; https://www.crossref.org/documentation/reference-linking/data-and-software-citation-deposit-guide/ ; https://www.crossref.org/documentation/schema-library/markup-guide-metadata-segments/relationships ; https://support.datacite.org/docs/rest-api ; https://support.datacite.org/docs/harvesting-datacite-doi-metadata ; https://www.rfc-editor.org/rfc/rfc9110.html . Existing reference-rot research includes Klein et al.(2014), https://doi.org/10.1371/journal.pone.0115253 . That historical study's rates are not assumed to describe this cohort or today's web. No scientific-priority claim.

## Exact bounded source cohort

Retrieve one Crossref response with rows=100; filter type:journal-article,relation.type:is-supplemented-by,relation.object-type:doi,from-pub-date:2019-01-01,until-pub-date:2019-12-31; sort=published; order=asc; select=DOI,relation,published,type. Preserve the exact response even where API ordering ties or current deposits later change. It is a bounded response, not a random or comprehensive sample. A relation filter can include objects of relations; qualify actual is-supplemented-by DOI entries and preserve subject/object asserted-by provenance, rather than assuming every returned record asserts a data link.

Keep only well-formed canonical DOI targets with prefixes 10.5061, 10.6084 or 10.5281, the fixed Dryad/Figshare/Zenodo families. These metadata-based source restrictions are fixed before any HTTP landing observation. Normalize ASCII DOI identifiers case-insensitively, strip an explicit doi.org wrapper, reject whitespace/control/userinfo/query ambiguity and retain the native token. Canonicalization is not a link-repair claim. Sort parent/target DOI pairs lexicographically. For each distinct candidate target, retrieve the corresponding DataCite public DOI metadata, at most 40 targets total. Require a public Findable record with resourceTypeGeneral=Dataset. Public metadata 404, a different type, ambiguous relation direction or assertion provenance or unsupported prefix is recorded with a distinct exclusion/unavailable reason, never silently converted to a broken link.

From those qualified facts select the first 16 pairs with unique parent DOI and unique dataset DOI, in that fixed order. If fewer than 16 qualify within the bounded response/40 metadata lookups, stop this cohort rather than expand a query, change a prefix or select by network success. Preserve every examined item, rejected relation, duplicate and qualification reason. The conditional cohort excludes non-Findable metadata and other repositories; it cannot estimate overall scholarly-link reliability. Parent relations are source assertions, not proof that the dataset substantively supports an article's claims.

Assign alternating sorted selected pairs to development and final groups: eight real source datasets in each, with no shared canonical dataset DOI or parent DOI. Reused repository platforms, versions and related research can still create dependence; no statistical independence is claimed from identifier separation. Add three clearly authored nonresolving DOI controls per phase, fixed in data/source_requests.json, with no real parent/article allegation. Controls are not observed broken scholarly links. Confirm their observed resolver/reference states; do not assume a control is negative merely from its invented identifier. Keep syntax-invalid inputs in local fixtures only.

## Request budget, provenance and stop states

The entire live acquisition is bounded to one 100-item Crossref cohort response, at most 40 DataCite qualification responses, 44 initial/repeat item observations across both phases, at most five redirects per observation, 22 browser reference inspections, and ten documentation/rights captures. Maximum streamed landing body 256 KiB, metadata 2 MiB per response, total private capture 100 MiB. One request at a time, at least two seconds between programmatic requests to the same host. Identify the study in User-Agent without inventing contact credentials or exposing a personal email. Capture actual UTC start/end, status, safe content/rate-limit/retry headers, transport exception category, URL chain, lengths/truncation and SHA256. Status or headers unavailable remain unavailable.

After 429 honor Retry-After if supplied; otherwise wait at least 60 seconds before one targeted retry, preserving the first receipt. A second 429 stops dependent acquisition until an external change; do not rotate identities, keys, proxies or endpoints to defeat limits. On login, CAPTCHA, browser security warning, mandatory agreement, payment, repeated transport failure or denied source access, preserve an unknown/blocked observation without bypass. An HTTP 403 is access uncertainty and is not automatically a permanent source-level failure or missing dataset. Do not repeatedly request a denied item; its repeat slot is recorded as not_requested_after_denial, not a fabricated response. Other items and offline work continue.

Probe only verified HTTPS URLs at doi.org, dx.doi.org, api.crossref.org, api.datacite.org, zenodo.org, datadryad.org, figshare.com or their documented public repository subdomains. Reject literal/private/local IPs, credentials, non-HTTPS schemes and off-allowlist redirects before connecting. An unsupported redirect is censored/unknown, not broken. No file-download endpoint, form submission, authenticated session, alert, issue to an external maintainer or notification is allowed. The check follows a DOI to its landing response only; data-file access is not tested. Preserve full raw URL chains privately, but strip query/fragment/userinfo from public receipts and scan for tokens/cookies/private contact data. Do not publish source HTML, tracking values or browser screenshots containing irrelevant account UI.

## Observations and independent reference labels

For each phase make a first bounded GET observation of all eleven items, with the fixed redirect/body guards. The repeat phase cannot start before 20 minutes after the latest completed first observation in that phase; enforce actual timestamps. Do other authorized study work between captures. No background loop, scheduled task or fabricated elapsed interval. Save every failed/unknown/truncated state. A saved 404/410 is an observed response, not proof of permanent data loss. Other 4xx/5xx, rate limits, transport errors, unsupported targets and access restrictions remain distinct.

Separately inspect each item's normal public browser landing/reference page once, without using its rule decision as the label. Record actual UI evidence, time, canonical URL and a minimal factual reference label: available_landing only when the visible resource metadata/dataset context matches the source DOI or source-record identity; not_found_control only when the authored control receives a visible matching not-found result; otherwise unknown. Record redirects and any access challenge. Agent inspection is not independent human expert validation, and browser/API paths can share backends. Source metadata alone cannot label an inaccessible landing as available, and a200 response alone is insufficient if it is a login/error page. Reference timing differs from probe timing; report disagreement with the observed browser reference, not omniscient same-instant truth. No raw data files are opened.

Require at least four clearly available real reference pages and all three clearly nonresolving controls in each phase before reporting a conditional false-alert comparison. Preserve every unknown and its denominator outside binary metrics. Failure of this evidence gate stops that conclusion; do not round unknowns into passes. Source-clean/clinical records, scholarly scientific validity and the contents of datasets are outside scope.

## Fixed rules, outputs and evaluation

There is no learned model, probability, random seed, tuning, imputation, optimized interval or selected operating threshold. The following two rules are authored comparators; retain all results.

Naive comparator: an observed terminal non-2xx response or transport failure from the first probe produces broken_alert. A syntax-invalid or never-requested item stays invalid/unknown, not a source allegation. This comparator intentionally illustrates overinterpretation; it is not the released tool recommendation.

Conservative triage: report observed_landing_response for a successful 2xx landing response, while data_file_availability remains not_tested. Emit review_doi_candidate only when both valid, uncensored observations return 404 or 410 and the repeated observation is at least 20 minutes later. This is a suggestion to check DOI routing/metadata, never a declaration that a dataset disappeared. Access/auth/rate-limit/server/transport failures, incomplete redirect chains, conflicting observations or unavailable repeats remain review_access_or_transport/unknown. A later 2xx is recorded as a transient first-probe issue, not silently replacing the earlier failure. Preserve the observed reference label separately rather than converting it into a fabricated HTTP success.

Export source pairs, complete request/reference states, both rule actions, reasons and event times for every item. On the evaluable browser-reference subset, report confusion counts and apparent false alerts/disagreements relative to available_landing; controls provide limited negative examples. Report precision/recall only where their denominators exist, reference coverage, deferred unknowns, control prevalence and real/control results separately. A conservative review candidate and the naive broken alert have different stated semantics; compare their alert workloads and reference disagreements with that qualification. No population rate, independent-observation CI, long-term availability, actual maintainer workload saving, repair, adoption or scientific-claim verification is established.

Development is eight real DOI groups and three controls. Commit source/identity/rights/observation meanings, fixed rules/checker, complete development observations/reference/results, fixtures and CLI exercise in a dependency manifest before any final-group landing observation or browser reference inspection. Source metadata qualification for all 16 groups is allowed before freeze but final availability is not probed. Then execute the unchanged pipeline on eight other real DOI groups and three controls, including the real-time repeat interval. Do not revise rules from final outcomes. Preserve any corrected post-test analysis as retrospective; a new confirmatory claim would need fresh protected links/times.

Independently parse the exact Crossref/DataCite originals using a separate reader/SQL key path and verify source tokens, unique parent/target groups, source type/rights scope and excluded items. Independently reconstruct canonicalization, redirects/allowed hosts, status categories, all time gaps and repeat eligibility, reference coverage, both rule actions and all confusion/count/rate denominators without importing the rule helpers. Fixtures cover real DOI syntax/normalization boundaries, private/off-host/credential URLs, redirects,403/404/410/429/5xx, missing/transient repeats, Retry-After, truncation, timestamps, matching/unknown reference identity and zero denominators. The offline CLI consumes captured sanitized observations and returns triage reasons, not a live crawler or maintainer message. Replay a full-history clone into separate paths without network or original overwrites. Verify all displayed numbers, source-to-SVG geometry and hashes, inspect every paper page, scope the five authored paper files, then require exact candidate/main CI, matching tested content, a remote annotated tag and accurate program metadata before counting completion.
